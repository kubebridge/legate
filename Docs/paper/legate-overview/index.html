1Overview

An agent harness, not an agent

Legate runs the conversation; the host owns the product around it.

Legate is an open-source (Apache 2.0) agent harness for .NET: a durable Akka.NET runtime for tool-using AI agents, written in F# with a C#-friendly public surface. A host registers it with AddLegate(...), configures LLM providers, tools, and storage, and gets sessions it can prompt at any time, steer mid-turn, abort, resume after a crash, and replay.

The mental model is the backend of an agentic CLI: a session, one primary verb (the user sends a message), a stream of events back, and the ability to answer, steer, or abort while the agent works. Two hosts are first-class: a CLI harness (single process, no database server, tools on the working directory, approval prompts) and a hosted multi-tenant service (clustered, Postgres and S3, sandboxed workspaces, headless sessions with webhooks).

Status: pre-release scaffolding. Legate 0.1.0 is published to nuget.org as a preview; expect breaking changes between 0.x releases. Docs/ARCHITECTURE.md in the repository is the normative target the implementation is converging on.

2Core concepts

Sessions, turns, and events

Seven terms cover most of the model.

TermMeaning
AgentA definition: model config, system prompt, tool set, skills, sub-agents, permission defaults.
SessionA conversation with one agent (switchable per turn). Has an id, tenant, title, state, transcript, inbox, and workspace binding. Lives until closed or expired.
UserMessageWhat the user sent. The only thing that starts a turn, journaled before it is acted on.
ReplyThe host answer to something the agent waits on: a permission decision or a question answer. Resumes a suspended turn, never starts one.
TurnOne run of the ReAct loop. Ends when the model stops calling tools, the host aborts, or the budget runs out; suspends while waiting on a reply. The lease and claim unit.
SessionEventFine-grained, ordered, journaled stream out of a session (turn started, text delta, tool call started, permission requested, turn completed, and more). Hosts render these.
SessionCellThe coarse transcript (user, assistant, tool call, tool result, system), derived from events, kept for replay and UI.

Session lifecycle: Idle to Running to (Idle, WaitingForInput, or Closed). Every side effect on behalf of a turn checks the turn claim token at the last moment; a correlation id is evidence, not authority.

3Interactive model

One runtime, three deployment shapes

Inspect a box for its responsibility, drill from context to containers to the turn loop, then play the prompt flow.

The interactive model loads with JavaScript. The architecture summary below remains available without it.

Verified against the repository at main, October 2026. Everything points inward to Legate.Abstractions; the Abstractions package depends on nothing else in the solution.

Context. A developer builds a host application on Legate libraries, wires LLM providers and tool servers, and serves end users. The harness itself is in-process libraries plus an Akka.NET actor system, not a separate service to deploy.

Containers. The session runtime (actors, dispatcher, ReAct loop) executes turns; the event journal (SQLite locally, Postgres hosted) persists the ordered event stream for resume and replay; the workspace runtime (HostDirectory, Process, Docker) gives tools a filesystem with confinement; the LLM layer (OpenAI-compatible, Anthropic, Google providers) serves model calls with admission control; the tool gateway (built-ins, MCP servers, sub-agents) executes calls behind the permission policy.

Turn loop. Claim the turn, run the ReAct loop, fence every side effect on the claim, journal every event, settle exactly once with an operation receipt, and notify observers. Compaction keeps model input bounded; transcripts stay complete.

4How it works

One prompt, end to end

Follow a user message from inbox to receipt.

  1. Prompt. The host appends a user message to the session inbox and asks for a turn, receiving an accepted-operation receipt for durable observation.
  2. Claim. The session actor drains the entry and claims the turn (lease-protected, fenced against takeovers and crash orphans).
  3. Loop. The ReAct loop calls the model, executes tool calls through the workspace, and streams text, reasoning, and tool events to the journal as they happen.
  4. Gate. A tool call the policy cannot decide alone suspends the turn with a permission request (or an agent question); the host reply resumes exactly that turn.
  5. Settle. When the model stops calling tools, the turn settles once: outcome recorded, observers notified by operation identity (never next-result FIFO), transcript cells derived.
  6. Observe and steer. Hosts render the event stream live, answer pending prompts, steer or abort mid-turn, and later resume or replay from any sequence number.

Failure paths keep the same shape: aborts, budget exhaustion, and loop faults settle explicitly; crash recovery rebuilds from the journal and continuation resumes under a fresh claim.

5Operations and limits

Running it and knowing the edges

Prerequisites, storage choices, recovery, and current limitations.

Prerequisites

.NET 10 SDK. Provider API keys from environment (ANTHROPIC_API_KEY, OPENAI_API_KEY, GOOGLE_API_KEY) or configuration. Docker only for container workspaces and the cluster smoke harness.

Storage

SQLite file for single-process hosts (resume works across processes). Postgres plus S3 for the hosted service, with shared versioned migrations. In-memory stores exist for tests.

Recovery

Leases expire, claims fence takeovers, the journal replays from any sequence, and settlement is idempotent. A restarted host reopens sessions and continues turns without duplicating effects.

Limits

Pre-release: breaking changes across 0.x. No old-format migration shims; unsupported journals are rejected with a clean start. Samples are hosts, not supported products.

Which sample should I run first?

samples/Dot is the interactive CLI with a full-screen transcript UI. samples/MinimalHost shows minimal wiring; samples/Headless runs sessions without a UI; samples/CSharpWebHost shows ASP.NET Core hosting.

How do sub-agents work?

The task tool runs a named sub-agent (for example explore with read-only tools, or general) as a nested turn sharing the session workspace and journal, with its own filtered tool pool.
