01 / Sessions

Working with sessions

A session holds a conversation with an agent across multiple turns. Your application sends messages, receives events, and handles requests for approval. It can also add instructions while the agent is working or stop the current turn.

The session stays open between turns, keeping its history and workspace binding for the next message.

Client API

Send a message

Use SessionClient to open a session and prompt it. A turn may include several model calls and tool executions before it returns a result.

For a configured host with a resolved client and an agent that does not require interactive approval:

var ct = CancellationToken.None;

var session = await client.OpenSessionAsync(
    agentId,
    new SessionOptions { Title = "Review the project" },
    ct);

TurnResult result = await client.PromptAndWaitAsync(
    session.Id,
    UserMessage.Text("Summarise this project's structure."),
    ct);

PromptAndWaitAsync sends a message and waits for the result. For an interactive application, use PromptAsync, Subscribe, and ReplyAsync so your interface can handle approval requests as they arrive.

Delivery modes

Choose how a message reaches the agent

When the session is idle, all three modes start a turn. When it is waiting for input, new messages join the inbox; ReplyAsync answers the pending request.

Queue

Wait for the current turn to finish, then process the message as a new turn. Use this for follow-up work.

Inject

Add the message to the current turn at the next model-loop boundary. Use this to clarify a request or add information while the agent is working.

Interrupt

Abort the running turn and start a new one with this message. Use this when the current request is no longer useful.

Session lifecycle

Handle approvals and questions

A turn can pause while it waits for permission to call a tool or for an answer from the host. The event stream identifies the request. Send a matching PermissionDecision or QuestionAnswer through ReplyAsync to continue the same turn.

A completed or aborted turn normally returns the session to Idle. Closing the session is a separate operation. Sessions opened with AutoClose close when their run finishes.
StateWhat it means
IdleThe session is open and ready for work.
RunningThe agent is processing a turn.
WaitingForInputThe turn is paused for a host reply.
ClosedThe session no longer accepts messages or replies.
Events and history

Read events and conversation history

Subscribe returns an IAsyncEnumerable<SessionEvent>. It reads stored events after the supplied sequence number, then continues with live events. Save the last processed sequence to reconnect from that point.

Read a page of events

Use ReadEventsAsync for a bounded page of journal events, ordered by sequence number.

Read the transcript

Use ReadTranscriptAsync for the conversation cells derived from journaled events.

Cluster subscriptions use at-least-once delivery. Use sequence numbers to ignore events you have already processed. See reconnecting to the event stream for replay and retention behaviour.

Patterns

Continue, branch, or finish the conversation

Wait for a result in an unattended workflow, fork the history to try another approach, or change the agent that handles future work.

Wait for a result

PromptAndWaitAsync reports an approval suspension rather than waiting for someone to answer it. Interactive hosts can register WaitForSettleAsync before prompting and handle replies alongside the event stream.

Cancelling either wait leaves the turn running. Use AbortAsync to stop the turn itself.

Fork a session

ForkAsync creates a new session with the source history up to a chosen event sequence. Continue from that point to try another approach. The source session is unaffected.

var fork = await client.ForkAsync(
    session.Id,
    upToSequence,
    cancellationToken);

Change agents

SetAgentAsync changes which agent handles future work. The change applies immediately when there is no active turn or pending inbox work; otherwise, it waits until that work has cleared. The session keeps its history.

Run unattended

Open a session with AutoClose and policies that resolve tool permissions and questions without user interaction. Add a completion sink if another service needs the result. Structured outcome mode gives the agent finish and fail tools.

Completion notifications use at-least-once delivery and include an idempotency key for deduplication.
