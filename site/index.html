01 / Sessions deep dive

Seven concepts, one client

The overview introduces Agent, Session, UserMessage, Reply, Turn, SessionEvent, and SessionCell. This page is the working reference: the client API, the delivery modes, the session state machine, and what headless really is.

Client API

Prompt, reply, read

Tasks, never Async. XML docs on every public member. Subscribe returns the live journal as an IAsyncEnumerable from any sequence cursor.

AreaMembers
SessionsOpenSession, ResumeSession, GetSession, ListSessions, Close, Fork, SetAgent
PromptingPrompt(sessionId, UserMessage, DeliveryMode) where DeliveryMode is Queue, Inject, or Interrupt
ReplyingReply(sessionId, Reply) with a PermissionDecision or a QuestionAnswer
ControlAbort, Compact
ReadingReadTranscript, ReadEvents(fromSequence), Subscribe(sessionId, fromSequence)
SugarPromptAndWait extension returning a TurnResult

Queue

Append to the inbox. The message waits its turn behind whatever is running.

Inject

Fold into the running turn at the next iteration boundary. Steering without aborting.

Interrupt

Abort the running turn and start fresh. The operator override.

State machine

Idle, Running, and back

A session lives until closed or expired. A turn suspends while it waits on a reply, and a reply resumes it without ever starting a new one.

Prompt starts, reply resumes, settle rests. Headless sessions close through the completion sink.
Patterns

Wait, fork, headless

Three recipes that fall out of the API without extra concepts.

// fire, stream, and wait for the terminal event
TurnResult result = await client.PromptAndWaitAsync(session.Id, msg);
// branch a session to try an alternative without losing history
var fork = await client.ForkAsync(session.Id);
// headless = session + AutoClose + AllowAll + completion sink
await client.CloseAsync(session.Id);

No job type

A headless run is a session opened with AutoClose, an AllowAll permission policy, an optional completion sink, and optionally Outcome = Structured (which gives the agent finish and fail tools).

Switch agents mid-stream

SetAgent swaps the agent for the next turn. The transcript, inbox, and journal stay with the session.
