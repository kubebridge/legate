Seven concepts

Interactive and unattended work use the same session model.

Agent

The model configuration, system prompt, tools, skills, sub-agents, and permission defaults.

Session Core

A conversation with an agent. Keeps its state, transcript, inbox, and workspace binding until closed or expired.

UserMessage

Text, files, or images sent by the user. A message can start a turn, join the queue, or steer running work.

Reply

The host's answer to a permission request or question. Resumes the suspended turn.

Turn Core

One run of the model and tool loop. Ends on completion, abort, or a limit; can pause for input. Runs under a claim.

SessionEvent

An event in the ordered journal, such as TurnStarted, ToolCallStarted, or TurnCompleted.

SessionCell

A transcript entry derived from journaled events for conversation history and display.

Legate.Abstractions

These contracts share a package with no Akka dependency.

A turn, step by step

01

Prompt enters the inbox

The message is appended to the session store. The dispatcher wakes the session actor, which runs locally or on a cluster node.

ISessionStore

The turn is claimed under a lease

The store grants one worker the claim. The runtime checks its token before invoking tools, and the stores reject writes from expired or replaced claims.

ClaimNextTurn

Workspace, agent, and model

The runtime binds the workspace, loads the agent's instructions and skills, and prepares the model client with the configured model policy and call limits.

IChatClient

Tools are assembled

The agent receives its configured built-ins, custom tools, and tools from registered sources such as MCP servers. Calls pass through the permission policy.

IPermissionPolicy

The model and tool loop runs

The agent calls the model, executes permitted tool calls, and returns results to the model. Recorded events reach subscribers, and injected messages join at iteration boundaries.

SessionEvent

The turn finishes

Usage is checkpointed and the turn settles. An interactive session returns to idle. AutoClose sessions close after their run and notify a configured completion sink.

Idle

02 / Durability

Recover after a node failure

Each turn runs under a renewable claim. If a node stops, another can take over after the lease expires. The session's recovery policy either starts a new attempt or records the interruption as a failure.

The interrupted turn is recorded as failed. The session is ready for another prompt.

Claim-protected writes

The store checks the current claim before accepting checkpoints, journal appends, or settlement. An expired or replaced claim is rejected.

Atomic store updates

Inbox appends, claims, renewals, usage checkpoints, and turn settlement are each applied atomically.

Tenant-scoped storage

Every store operation includes a TenantId. Storage providers scope reads and writes to that tenant.

03 / Build

Choose how to host it

Register Legate in your application's dependency injection container. Choose the model providers, tools, storage, and workspace that fit your deployment.

CLI harness

Run in one process with no database server. Use SQLite for persistent sessions and a host-directory workspace for tools that work on local files.

The LegateCli sample demonstrates interactive approvals with in-memory storage. CSharpHost shows the session API in a C# Generic Host.

Hosted service

Use Postgres for shared session state, S3 for blobs, and Docker workspaces for container isolation. Add clustering when the service needs multiple nodes.

MinimalHost exposes HTTP endpoints and an SSE event stream. Headless demonstrates AutoClose with a completion webhook.
