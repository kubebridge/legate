Add Legate to your .NET application

Legate runs inside an ASP.NET Core application, a .NET Generic Host, or a CLI. Register it with AddLegate, configure a model provider, storage, and a workspace, then use SessionClient to open and prompt sessions.

The runtime is written in F# and exposes a C#-friendly API using .NET tasks and async event streams.

Getting started

Start with a working sample

The samples show how to configure the runtime and drive a session from application code. From a checkout, with the .NET 10 SDK installed, build the solution and run the scripted CLI.

dotnet fsi build.fsx
dotnet run --project samples/LegateCli -- --scripted

Scripted mode exercises the CLI without provider keys or network calls. To use a live model, follow the CLI guide to configure a provider.

Storage and execution

Choose storage and a workspace

Storage keeps session state and events. The workspace determines where tools run and which files they can access. Choose each for your deployment.

Local applications

Use SQLite for sessions and events in a local database file. Use Legate.Workspace.HostDirectory when tools should work in a selected host directory.

Hosted services

Use Postgres for shared session state and events. Add S3 for blobs and agent packages, and Docker workspaces when tool execution needs container isolation.

Tests and experiments

Use in-memory stores and a process workspace. This configuration requires no database server or container runtime. Its session data lasts for the process lifetime.

Host integration

Configure your application's policies

The host decides who can use the agent, which tools it can call, and where those tools run. Register implementations of these interfaces to connect Legate to your application.

InterfaceWhat it controls
ISessionAdmissionPolicyWhether to accept a session open or prompt.
IPermissionPolicyWhether a tool call is allowed, denied, or requires approval.
IModelPolicyWhich model to use for a call.
IToolSourceWhich additional tools are available. The MCP integration uses this interface.
IWorkspaceRuntimeWhere tool execution and file operations take place.
IUsageObserverHow your application records token-usage checkpoints and settled usage.

Legate reports token counts. Your application can use those counts for metering or billing.

Additional interfaces cover ISessionCompletionSink for completion notifications and IArtifactQuota for artifact quotas.

Development

Build and test from source

The core test suite runs without external services. Integration suites use Postgres, Redis, S3-compatible storage, and Docker where needed. CI also runs the sample applications, the cluster recovery test, and package creation.

dotnet fsi build.fsx
dotnet fsi build.fsx -t Test
dotnet fsi build.fsx -t CheckFormat

Legate is currently on the 0.x release line. Public APIs may change between releases.
