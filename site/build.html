03 / Build

Add Legate to your .NET application

Register Legate in your .NET host, then open and prompt sessions from application code. Your application chooses the model provider, persistence, tools, and execution environment.

Use it in ASP.NET Core services, background workers, or a CLI. The F# runtime exposes a C#-friendly API with .NET tasks and async event streams.

01 / Integration

Connect your application in C#

Follow these steps in an ASP.NET Core application's Program.cs. Choose a provider and register an agent, bind the request pipeline, then use a session client in your handlers.

Before you begin: packages, credentials, and imports

Use the .NET 10 Web SDK with Legate.AspNetCore and Legate.Llm.OpenAI. Set Legate__Llm__Providers__openai__ApiKey through your deployment's secret configuration. The snippets use the Web SDK's implicit imports plus these namespaces. For a key-free scripted version, run CSharpWebHost.

using Legate;
using Legate.AspNetCore;
using Legate.Llm.OpenAI;
using SessionOptions = Legate.SessionOptions;

Register the runtime

Bind configuration, choose OpenAI, and register the agent used below. Code configuration runs after the Legate section is bound.

var builder = WebApplication.CreateBuilder(args);
var agentId = AgentId.Parse("01ARZ3NDEKTSV4RRFFQ69G5FAV");
builder.Services.AddLegate(builder.Configuration, legate =>
{
    legate.Llm.AddOpenAI(builder.Configuration);
    legate.Agents.Add("assistant", agent =>
    {
        agent.Id = agentId;
        agent.Model = ModelReference.Parse("openai/gpt-4o-mini");
        agent.SystemPrompt = "Answer briefly.";
        return agent;
    });
});

The local profile pairs session and event stores in one in-memory database and uses a process workspace under the application's content root. Metadata is lost on restart. Process tools run without a sandbox and are unsafe for untrusted agents. Choose persistence and execution explicitly for production.

Bind the request pipeline

UseLegate binds the request's tenant client. Your application still owns authentication, authorization, routing, and endpoints.

var app = builder.Build();
app.UseLegate();

This example is single-tenant with TenantId.Default. A multitenant application supplies a trusted resolver and complete declared bindings. Place this middleware after routing when the resolver needs endpoint metadata, after your authentication and authorization middleware, and before session handlers. Minimal hosting supplies routing automatically.

Open a session and prompt it

Inject the request-bound client, open the registered agent's session, and prompt with plain text. Omitted delivery is Queue; omitted cancellation is None.

app.MapPost("/ask", async (SessionClient client) =>
{
    var session = await client.OpenSessionAsync(agentId);
    var result = await client.PromptAndWaitAsync(
        session.Id, "Hello, Legate!");
    return Results.Ok(result.AssistantText);
});
await app.RunAsync();

Hosted services own startup and shutdown. Background workers use ISessionClientFactory.GetClient(tenant) after startup instead of resolving a request-scoped client.

Choose event handling or explicit controls

Within a handler, use Subscribe plus ReplyAsync for approval workflows. The stream defaults to exclusive cursor zero. Pass a cursor to reconnect.

await foreach (var evt in client.Subscribe(session.Id, cancellationToken))
{
    if (evt is PermissionRequestedEvent asked)
        await client.ReplyAsync(session.Id,
            new PermissionDecision(asked.RequestId, PermissionDecisionKind.AllowOnce),
            cancellationToken);
    if (evt is TurnCompletedEvent or TurnFailedEvent or TurnAbortedEvent)
        break;
}

A standalone settle waiter must be registered before prompting; it is not durable retrieval of an earlier result. Its omitted bound is the configured client default of five minutes. PromptAndWaitAsync registers the waiter first but does not replace explicit suspension handling.

var settled = client.WaitForSettleAsync(session.Id);
await client.PromptAsync(session.Id, "Continue");
var result = await settled;

For explicit request control, pass the request token. Cancellation may prevent admission; after acceptance it abandons the supplied operation, not the turn. Aborting is a separate targeted control operation.

await client.PromptAsync(session.Id, "Continue",
    DeliveryMode.Queue, context.RequestAborted);
02 / Deployment

Match persistence and execution to your host

The example above keeps data in memory and runs tools in the host process. For your deployment, choose how session state survives restarts and where tools can access files.

Local applications

Use SQLite for sessions and events in a local database file. Use Legate.Workspace.HostDirectory when tools should work in a selected host directory.

Hosted services

Use Postgres for shared session state and events. Add S3 for blobs and agent packages, and Docker workspaces when tool execution needs container isolation.

Tests and experiments

Use in-memory stores and a process workspace. This configuration requires no database server or container runtime. Its session data lasts for the process lifetime.

Local mode is the default. Cluster mode rejects the adapter's implicit local stores and workspace. Every node needs explicitly registered, compatible session and journal stores, a chosen execution runtime, and symmetric trusted tenant bindings, models, tools, and policies. Your deployment supplies genuinely shared durable storage; startup verifies wiring and atomic settlement compatibility, not backend durability or topology. Clustering does not automatically distribute local data or LLM admission. Redis is needed only when distributed admission is enabled. The hosted-service guide and adapter cluster sample cover these choices.

03 / Application behavior

Connect tools and policies

Once the runtime is registered, connect your application's admission rules, tool permissions, model selection, and usage reporting through these interfaces.

InterfaceWhat it controls
ISessionAdmissionPolicyWhether to accept a session open or prompt.
IPermissionPolicyWhether a tool call is allowed, denied, or requires approval.
IModelPolicyWhich model to use for a call.
IToolSourceWhich additional tools are available. The MCP integration uses this interface.
IUsageObserverHow your application records token-usage checkpoints and settled usage.

Register a workspace through IWorkspaceRuntime for the execution environment chosen above. Use ISessionCompletionSink for completion notifications and IArtifactQuota for artifact quotas.

Legate reports token counts for application metering or billing. See the configuration reference for host options.

Run the C# sample without provider credentials

From a repository checkout with the .NET 10 SDK installed, run the scripted C# host. It uses local model responses without provider keys or network calls.

dotnet run --project samples/CSharpWebHost -- --urls http://127.0.0.1:5080
dotnet run --project samples/CSharpHost -- --scripted

For an HTTP host, follow the hosted-service guide. For an interactive terminal, follow the CLI guide.

06 / Source development

Build and test from source

To develop Legate itself or validate a source checkout, use the repository build targets. The core tests run without external services; provider integration suites use Postgres, Redis, S3-compatible storage, and Docker where needed.

dotnet fsi build.fsx -- -t Build
dotnet fsi build.fsx -- -t Test
dotnet fsi build.fsx -- -t CheckFormat

Legate is currently on the 0.x release line. Public APIs may change between releases.
